# Production Runbook

## Deployment Checklist

### Pre-deployment
- [ ] All environment variables configured (see README.md)
- [ ] PostgreSQL database provisioned and accessible
- [ ] Redis instance running
- [ ] Stripe production keys obtained and configured
- [ ] Stripe webhook endpoint registered with production URL
- [ ] Cloudflare R2 bucket created and credentials configured
- [ ] Resend API key obtained with verified sender domain
- [ ] Encryption key generated (`openssl rand -base64 32`)
- [ ] CORS origins set to production frontend domain

### Backend Deployment (Render)
1. Connect GitHub repository to Render
2. Create new Web Service, select Python environment
3. Set build command: `pip install -r requirements.txt`
4. Set start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
5. Add all environment variables from `.env.example`
6. Set `ENVIRONMENT=production`
7. Set `STORAGE_TYPE=r2`
8. Deploy and verify health endpoint: `GET /health`
9. Run migrations: `alembic upgrade head`

### Frontend Deployment (Vercel)
1. Connect GitHub repository to Vercel
2. Set framework preset to Next.js
3. Add environment variables:
   - `NEXT_PUBLIC_API_URL` = backend production URL
   - `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` = Stripe production publishable key
4. Deploy and verify landing page loads

### Post-deployment Verification
- [ ] Registration and email verification working
- [ ] Login returns valid JWT tokens
- [ ] Stripe checkout creates session and redirects
- [ ] Stripe webhook receives events (check Stripe dashboard)
- [ ] Workflow steps save and resume correctly
- [ ] Document generation produces valid PDFs
- [ ] Document download via signed URLs works
- [ ] Compliance dashboard loads deadlines
- [ ] Email notifications sending (check Resend dashboard)

## Monitoring

### Health Check
- Backend: `GET /health` returns `{"status": "ok"}`
- Frontend: Vercel deployment status dashboard

### Error Tracking
- Sentry dashboard (if configured): monitor for 5xx errors
- Render logs: check for unhandled exceptions

### Stripe Monitoring
- Stripe Dashboard > Developers > Webhooks: verify events processing
- Check for failed webhook deliveries
- Verify no events stuck in "pending" status

## Common Operations

### Database Migrations
```bash
# Apply pending migrations
alembic upgrade head

# Check current migration version
alembic current

# Rollback one migration
alembic downgrade -1
```

### Manual Entitlement Override
Use direct database query (logged to audit_logs):
```sql
UPDATE entitlements
SET subscription_status = 'active',
    subscription_tier = 'complete',
    updated_at = NOW()
WHERE workspace_id = '<workspace_uuid>';

INSERT INTO audit_logs (id, workspace_id, actor_type, actor_id, event_type, previous_state, new_state, extra_data, created_at)
VALUES (gen_random_uuid(), '<workspace_uuid>', 'admin', 'manual', 'entitlement.manual_override', '<previous_status>', 'active', '{"reason": "manual override"}', NOW());
```

### Stripe Webhook Re-delivery
1. Go to Stripe Dashboard > Developers > Webhooks
2. Select the endpoint
3. Find the failed event
4. Click "Resend"

### Document Regeneration
Documents can be regenerated by calling `POST /api/v1/documents/generate` with a valid access token for a user whose workflow is completed.

## Incident Response

### User Cannot Access After Payment
1. Check Stripe Dashboard for payment status
2. Check `stripe_events` table for webhook delivery
3. Check `entitlements` table for current status
4. If webhook was missed, manually update entitlement (see above)

### Webhook Failures
1. Check Render logs for error messages
2. Check `stripe_events` table for `processing_status = 'failed'`
3. Verify `STRIPE_WEBHOOK_SECRET` matches Stripe dashboard
4. Re-deliver failed events from Stripe dashboard

### Database Connection Issues
1. Check Render dashboard for database status
2. Verify `DATABASE_URL` is correct
3. Check connection pool limits

### Email Not Sending
1. Check Resend dashboard for delivery status
2. Verify `RESEND_API_KEY` is valid
3. Check sender domain verification in Resend
4. Check Render logs for email-related errors
